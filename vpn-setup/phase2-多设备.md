# P2 · 多设备：全家十几台终端共用

前提：[P1](./phase1-跑通.md) 已跑通且稳定几天。本阶段把节点扩展给全家设备使用。

有两条路线，按需要的"管理精细度"二选一（也可先 A 后 B）。

> **本人需求：给每个使用的人单独配一个账号** → 直接走**路线 B（3X-UI 面板）**。
> 路线 A 是全家共用一条链接，做不到按人区分；要按人管理就用 B。

---

## 路线 A：一个节点，所有设备共用（最简单，先用这个）

直接把 P1 生成的那条 `vless://...` 链接发给每台设备导入即可。

- 操作：每台设备装客户端 → 粘贴同一条链接 → 开代理。
- 优点：零额外配置，加新设备 = 复制一次链接。
- 缺点：全家共用一个"身份"，无法单独看/禁用某台设备。
- **十来个终端日常用，这个完全够。** 觉得不够再上路线 B。

### 带宽提醒
设备多了，瓶颈在 VPS 带宽/月流量，不在数量。
全家同时刷网页、聊天没问题；多人**同时看 4K / 大量下载**可能挤带宽。
如出现卡顿 → 升级到 **≥1Gbps 端口、月流量 ≥1TB** 的套餐，或上 [P3](./phase3-冗余备份.md) 分流到第二台机器。

---

## 路线 B：3X-UI 面板，每设备/每家人独立账号（精细管理）

想单独管理（看谁在用、限速、禁用、分流量）就装面板。

### 安装 3X-UI

```bash
bash <(curl -Ls https://raw.githubusercontent.com/mhsanaei/3x-ui/master/install.sh)
```

装完按提示设置**面板端口**和**用户名/密码**，然后浏览器访问：

```
http://SERVER_IP:面板端口
```

> 安全：面板端口不要用默认；建议设强密码；有条件用域名 + TLS 给面板加密访问。

### 给每个人建一个账号（核心需求）

3X-UI 里，一个 Inbound（入站节点）下可以挂很多个 **client（客户端账号）**，
每个 client 有自己独立的 UUID 和导出链接 —— 这就是"一人一号"。

操作步骤：

1. 新建一个 Inbound：协议选 **VLESS + Reality**（和 P1 一致），端口/伪装域名用默认即可。
2. 进入这个 Inbound，点 **+ 添加客户端（Add Client）**，为每个人各加一个：
   - **Email/备注**：填好辨识名，按"人"而不是"设备"命名，例如 `爸爸`、`妈妈`、`我`、`妹妹`。
   - **UUID**：留空让它自动生成（每人不同，互不通用）。
   - 可选：**到期时间**、**流量上限**、**限速** —— 按人单独设。
3. 保存后，点该 client 旁的二维码 / 链接图标，导出他专属的 `vless://...` 链接，发给本人导入。
4. 一个人有多台设备：可以让他**多台共用同一条自己的链接**（够用），
   也可以为他再建 `爸爸-手机`、`爸爸-平板` 多个账号（要更细的话）。

### 建议的账号规划（十几个终端 / 多人）

| 备注名 | 给谁 | 备注 |
|--------|------|------|
| `me-laptop` / `me-phone` | 本人 | 自己多设备可分开，方便排查 |
| `dad` | 爸爸 | 一人一条，多设备共用 |
| `mom` | 妈妈 | |
| `sister` | 妹妹 | |
| … | … | 用到再加，不限数量 |

### 这样做的好处（正是"一人一号"的价值）
- **按人看流量**：面板里清楚每个人用了多少、谁在线。
- **单独禁用**：某人不再用、或链接泄露/设备丢失 → 只禁他一个，不影响别人。
- **单独限制**：给某人设流量上限 / 限速 / 到期时间。
- **方便分发**：每人一个固定不变的链接 / 二维码，发一次长期用。

### 维护小贴士
- 把"备注名 ↔ 给谁"记在一个小表里，时间久了不会忘谁是谁。
- 链接里包含 UUID，等于密码，**让每个人自己保管，别群发到大群里**。
- 需要换号：删掉旧 client、新建一个，把新链接发给本人即可（旧的立即失效）。

## 实战要点 & 排错（3X-UI v3.x，亲测）

### 安装时的选择
- 安装脚本问数据库：选 **SQLite**（个人/家用够用）。
- 自定义端口/账号密码：选 **y**，端口用五位随机数、密码用强密码、访问路径保持随机串。
- SSL 证书：选 **「Let's Encrypt for IP Address」**——没有域名也能给面板上 HTTPS（6 天有效、自动续期）。ACME 监听端口用默认 **80**。
- 装完会打印**用户名/密码/端口/路径/访问URL**，全部存好；首次登录后**立刻改一次密码**。
- 查看当前端口/路径：`x-ui settings`；忘记密码：`x-ui` 菜单里「重置用户名密码」。
- 让面板开机自启：`x-ui enable`。

### 新建 VLESS+Reality 入站的关键填法
- Stream → Transmission 选 **RAW**（新版 Xray 把 “TCP” 改名叫 RAW，就是它）。
- Protocol → Decryption/Encryption 都 **none**；别点 `X25519 auth / ML-KEM-768 auth`。
- Security → **Reality**，uTLS=**chrome**，点 **Get New Cert** 自动生成公钥/私钥。
- **mldsa65 Seed / Verify 留空**（抗量子选项，客户端多不支持，填了会连不上）。
- 加客户端：Clients → **+ Add Clients** → Basics 填 Email(人名)+ 勾 **Attached inbounds** → Credentials 的 **Flow = xtls-rprx-vision**。

### ⚠️ 头号大坑：Reality 的 Target 必须和 SNI 同一个站
3X-UI 新建入站时，**SNI(serverNames)** 和 **Target(dest)** 是两个独立字段，
默认 Target 可能是 `aws.amazon.com:443`，而你把 SNI 改成了 `www.oracle.com`——
**两者不一致 → Reality 握手必失败**。

- 症状：客户端能导入、VPN 能开、`nc/curl` 测端口通，但**网页全打不开、超时**；
  面板里该客户端显示 **Online: Offline / Last Online: `-`**（从未成功连接）。
- 原理：SNI 和 dest 不是同一网站，证书对不上，服务器把你当“真实访客”转发到 dest，代理隧道不成立。
- **修复**：编辑入站 → Security → 把 **Target 改成和 SNI 同一个站**（如都用 `www.oracle.com:443` / `www.oracle.com`）→ 保存 → `x-ui restart`。客户端不用重导。

### 排错命令（在服务器上跑）
```bash
ss -tlnp | grep ':443'                 # 确认 xray 在监听 443
curl -sI --max-time 8 https://你的dest # 确认 dest(目标站)从服务器可达
# 查看运行中的 Reality 实际参数（serverNames / shortIds / target）：
sed -n '/realitySettings/,/xver/p' /usr/local/x-ui/bin/config.json
```
把**客户端链接里的 `sni` / `sid`** 与服务器的 **serverNames / shortIds** 逐一对上即可定位。

### 切换到面板后的收尾
P1 用 233boy 脚本建的旧节点（如端口 17947）已不需要，关掉避免混淆：
```bash
systemctl disable --now xray     # 只停旧节点，不影响 x-ui 面板
ss -tlnp | grep 17947            # 无输出即已关闭
```
